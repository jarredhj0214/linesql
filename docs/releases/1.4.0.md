# LineSQL 1.4.0

LineSQL 1.4.0 includes the Spark CTE lineage performance fix from [PR #6](https://github.com/jarredhj0214/linesql/pull/6). Maven coordinates retain the group ID `io.github.jarredhj0214`; the runtime target remains Java 8.

## Spark CTE performance

Nested, wide CTEs can contain many columns that refer to the same physical source tables. Previously, registering every source-column occurrence refreshed all projection lineage, even when the table was already registered. Spark now registers distinct source tables in insertion order once per derived relation.

The fix preserves table lineage, column lineage, column usages, diagnostics, and existing alias handling. It does not change public APIs.

## Validation

- The full 365-test suite passed locally and on the JDK 11 GitHub workflow for the fix.
- A generated 768-column, 12-CTE regression exceeded 30 seconds on the previous implementation and passes with the fix.
- A separate private 28,306-character query took 15.563 seconds before the fix and 3.866 seconds afterward in the same local Java 8 harness; complete serialized results were structurally identical. These local timings are not production latency guarantees.

## Upgrading

Use version `1.4.0` for `linesql-all`, individual dialect modules, or the CLI. Version 1.3.0 is already released, so the fix is distributed under a new version rather than replacing existing artifacts.
