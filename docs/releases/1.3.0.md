# LineSQL 1.3.0

LineSQL 1.3.0 expands SQL parsing and improves table lineage, column lineage, and clause references across the nine bundled dialects. The Maven coordinates retain the group ID `io.github.jarredhj0214` and use version `1.3.0`. The runtime target is Java 8.

## Dialect changes

- **PostgreSQL.** Improved lineage through data-modifying CTEs, `RETURNING` row aliases, `JOIN USING` aliases, row comparisons, and `OVERLAPS`. Added coverage for `COPY`, temporary views, row locks, multi-action `ALTER TABLE`, and temporal key constraints.
- **Flink.** Expanded support for `EXECUTE INSERT`, `EXECUTE SELECT`, compiled plans, statement sets, and materialized tables. Static partition values preserve the positions of data projections. Session catalog and database changes qualify physical relations and scope temporary views.
- **SQL Server.** Improved automatic recognition of temporary tables, clustered and nonclustered indexes, `DBCC`, and native `EXEC` forms. `sp_columns` preserves catalog, schema, table, and column argument boundaries. `INSERT ... EXEC sys.sp_executesql` traces one literal `SELECT`, with positional write lineage when the explicit target columns match the known projection width.
- **Oracle and OceanBase.** Improved outer `JOIN USING` lineage. Oracle also gains stronger row-assignment and JSON `RETURNING` coverage.
- **MySQL and StarRocks.** Improved recursive CTE and literal prepared SQL lineage. StarRocks also tracks script catalog and database switches and resolves catalog-qualified column references.
- **Spark and Hive.** Spark tracks catalog and database switches, temporary views, and supported literal dynamic SQL. Hive carries database context through nested reads and writes and extracts lineage from standalone and lateral `TABLE VALUES` queries.

## Upgrading

Specify the dialect for production inputs when the source engine is known. A standalone `INSERT ... ON CONFLICT DO NOTHING` still defaults to PostgreSQL. Flink callers can pass the Flink dialect explicitly or use Flink-specific syntax such as `EXECUTE INSERT` when it fits the script.

The public regression corpus grew from 3,462 to 4,104 cases, with column-lineage assertions in 2,104 cases. Explicit dialect selection parsed 99.90% of the current corpus. The four remaining cases exercise expected diagnostics or unresolved dynamic SQL. These figures measure the public corpus. See [Benchmark and Coverage](../benchmark.md) and [Supported Scenarios](../supported-scenarios.md) for the scope of the assertions.
